2. DATABASE SCHEMA (MongoDB)
====================================================

--- USERS ---
User {
  _id,
  name,
  email,
  password,
  balance: Number,
  totalEarnings: Number,
  currentPackageCode: String | null,
  activeSessionId: ObjectId | null,

--- TASK PACKAGES ---
TaskPackage {

Task {
  _id,

UserTaskSession {

====================================================
3. API ENDPOINTS (NODE/EXPRESS)
====================================================

--- AUTH ---
POST /api/auth/login
POST /api/auth/register

--- ADMIN ---
POST /api/admin/package/create
PUT /api/admin/package/:code/update
POST /api/admin/package/:code/task/add
PUT /api/admin/task/:taskId/update
POST /api/admin/assign-package
BODY: { userId, packageCode }

--- USER TASK FLOW ---

1. START TASK REQUEST
POST /api/task/start
BODY: { userId, source: "amazon" }

LOGIC:
- Create task session OR return existing pending session
- Send request to admin approval queue

---

2. ADMIN APPROVAL
POST /api/admin/task/approve
BODY: { userId, packageCode }

LOGIC:
- Assign package to user
- Create UserTaskSession
- Set currentTaskIndex = 0
- Return session

---

3. GET ACTIVE SESSION
GET /api/task/session/:userId

RETURN:
- packageCode
- currentTask
- balance
- progress
- required/deposit status

---

4. GET CURRENT TASK POPUP
GET /api/task/current/:userId

RETURN:
- currentTask based on session index
- must strictly match packageCode tasks sorted by order

---

5. COMPLETE TASK
POST /api/task/complete
BODY: { userId, taskId }

LOGIC:
- validate task belongs to active package
- check required/deposit condition
- update balance
- increment session index
- log transaction
- return next task

---

6. DEPOSIT (REQUIRED TASK)
POST /api/task/deposit
BODY: { userId, amount }

====================================================
4. FRONTEND STATE FLOW (REACT / NEXT.JS)
====================================================

--- GLOBAL STATE (Redux/Zustand Context) ---

State:
{
  user,
  session,
  currentTask,
  loading,
  popupVisible,
  approvalStatus,
  balance,
  packageCode
}

---

--- FLOW LOGIC ---

STEP 1: USER CLICKS START TASK
startTask()

→ call /api/task/start
→ show "waiting for admin approval screen"
→ DO NOT show dashboard yet

---

STEP 2: ADMIN APPROVES
poll or websocket:

if (approved):
  fetch /api/task/session
  set session active
  show popup

---

STEP 3: TASK POPUP ENGINE

IF session.status === "active":
  show <TaskPopup />

TaskPopup logic:

currentTask = session.tasks[session.currentTaskIndex]

Render ONLY this task.

NO LIST VIEW unless explicitly required.

---

STEP 4: COMPLETE TASK

onComplete(taskId):
  call /api/task/complete
  update session
  increment index
  refresh popup

---

STEP 5: REQUIRED TASK HANDLING

IF currentTask.isRequired === true:
  IF balance < depositAmount:
     show DepositModal
     block completion
  ELSE:
     allow completion

---

STEP 6: SESSION RESTORE (IMPORTANT FIX)

On app reload:

GET /api/task/session

IF session exists:
  restore:
    packageCode
    currentTaskIndex
    popup state
    balance
    progress

DO NOT reset session.
